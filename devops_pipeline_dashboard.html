Q1: How does Jenkins execute the automated pipeline?
The Jenkins pipeline is written in a declarative Jenkinsfile located in the root of the repository. Whenever code is pushed to GitHub, a webhook or SCM poll triggers the 4 stages: 1) Checkout (pulls code from Pavishnu-BK repo), 2) Build (builds Docker image), 3) Test (executes Pytest in container), and 4) Deploy (deploys via Ansible). If any test fails in Stage 3, the pipeline terminates immediately with RED status and prevents deployment.
Q2: Why is Docker used instead of running directly on the host?
Docker eliminates the "it works on my machine" problem by bundling Python 3.11, all required pip packages, SQLite dependencies, and system configurations into a portable lightweight container image based on python:3.11-slim. The database is mounted on a persistent volume (/app/data) so metric data survives container restarts.
Q3: How are Ansible and Docker linked together?
Ansible operates through the playbook cloud-monitoring-deploy.yml using the community.docker.docker_container module. It ensures idempotent configuration: if the container is already running with the target image and port configuration, Ansible leaves it intact. If there are changes, it seamlessly recreates the container without downtime.
Q4: What automated tests are validated in the Pytest suite?
There are 11 unit and integration tests in test_app.py: SQLite schema creation, live psutil hardware extraction, threshold breach calculation, alert deduplication (ensuring no duplicate spam), automated recovery/resolution logic, configuration setting updates, HTTP status codes, and JSON API payloads for /health and /metrics.
